# Задачі

Одна задача — один файл `tasks/NNN-частина-коротка-назва.md` (D88). Частина в назві:

| Код | Частина |
| --- | --- |
| `back` | Бекенд |
| `front` | Фронтенд |
| `api` | Контракт API (спільне) |
| `docs` | Документи й дані (каталоги, джерела NASA) |
| `assets` | Асети (фото, музика) |
| `infra` | Інфраструктура |
| `submit` | Подача |

Заголовок файлу — `# NNN · Частина · Назва`, у шапці — рядок `Коротко:` з описом
задачі одним реченням. Гілка — `task/NNN-частина-коротка-назва`. Окремі файли замість спільного
списку, щоб гілки різних учасників не конфліктували.

## Як розбиваємо роботу

- Задача закривається однією гілкою й одним злиттям у `main`; орієнтир — кілька годин.
- Кожна задача має **власну зону файлів**. Дві задачі в роботі не повинні змінювати ті
  самі файли.
- Задача належить до однієї частини: бекенд або фронтенд. Задач, що змінюють обидві,
  не створюємо — їх ділимо на дві.
- Спільні контракти (структури даних, інтерфейси між модулями) виносяться в окрему
  задачу, яка вливається першою; решта від неї залежить.
- Виконавця призначає команда під час створення задачі, а не агент.

## Як працювати із задачею

1. Підтягни `main`, створи гілку `task/NNN-частина-коротка-назва`.
2. Постав у файлі задачі статус `in progress`.
3. Роби лише описане в задачі й лише в її зоні файлів. Знайшов щось поза межами —
   запиши в «Нотатки», не виправляй.
4. Перевір критерії готовності, постав статус `done`. Гілку вливають у `main` лише через
   pull request (D99), CI має бути зеленим (D100).

## Статуси

`todo` · `in progress` · `blocked` (вкажи чим) · `done`
