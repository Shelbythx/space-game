## Мета

Справжні магнітні бурі NASA в польоті (D83) з дотриманням детермінізму (D65).

## Обсяг

- Модуль `SpaceWeather`: клієнт `https://api.nasa.gov/DONKI/GST`, ключ зі змінної `NASA_API_KEY` (за замовчуванням `DEMO_KEY`).
- Seed → історичний 12-місячний період у межах 2010–2025; бурі з Kp → дні місії.
- Кеш у таблиці `space_weather_cache`; API недоступний → кеш; нема кешу → подія `spaceWeatherUnavailable`.
- Публічний інтерфейс для `Simulation`: бурі за періодом.
- Тести з записаною відповіддю API (без мережі).

## Зона файлів

- `backend/src/**/SpaceWeather/`, міграція таблиці кешу

## Критерії готовності

- [x] Той самий seed дає ті самі бурі (тест).
- [x] Без мережі симуляція не падає.

## Нотатки

- 15.11.2026 (Claude, сесія Khudashchov, D101). Гілка — від 005 (потрібен `ISpaceWeatherSource`).
- **api.nasa.gov обмежує DONKI вікном ≤ 60 днів** («Date range cannot exceed 60 days»), тож
  рік ділиться на 7 запитів; перший запит періоду ~4–5 с, далі — з кешу (~25 мс).
  `DEMO_KEY` має ліміт запитів на годину — для показу журі краще свій `NASA_API_KEY`.
- Seed → період: 12 місяців із початком від 01.01.2010 до 01.01.2025 (кінець ≤ 31.12.2025),
  `start = 2010-01-01 + (seed mod 5480)`. Буря = найбільший Kp у `allKpIndex`, день місії =
  дата цього Kp − початок періоду.
- Кеш: таблиця `space_weather_cache` (міграція `SpaceWeatherCache`), якщо є рядок
  підключення; без бази — кеш у пам'яті. Немає мережі й кешу → `Available = false` →
  подія `spaceWeatherUnavailable`, симуляція не падає (тест).
- Запис у кеш і читання з нього локально на PostgreSQL не перевірено: на цій машині ще немає
  ролі `spacegame` (див. `backend/README.md`). Тести — на кеші в пам'яті й записаній
  відповіді DONKI (`tests/…/Fixtures/donki-gst-2015-03-01_2015-04-29.json`).
- Запис `SpaceWeather` у `Simulation/Model` перейменовано на `SpaceWeatherData` (конфлікт із
  простором імен модуля). Тести ендпоінтів підмінюють джерело на `NoSpaceWeather` (без мережі).
